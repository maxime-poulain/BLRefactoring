# 0064 — Write this repository in American English

- **Status:** Accepted — amended by [0066](0066-close-the-spelling-rules-selection-against-its-exemptions.md): the selection is closed against its exemptions, so a file governed by neither fails the build
- **Date:** 2026-08-10

## Context

This repository had two spellings of the same word and no way to tell which was meant.

`AdrCatalog` is a helper in the architecture suite. The controller, the detail query, the detail DTO
and the route that carry the same noun in the domain's own vocabulary all wrote it the longer way,
with the French ending. Both name the same idea. Nothing anywhere said which one a new file should
use, so the answer was whichever the author had grown up with — and the count made that plain: 810
occurrences of the longer spelling against 17 of `Catalog`, and 163 of the `-our` form of *behavior*
against a `ValidationPipelineBehavior` that only spells it the short way because the framework's
interface does.

The framework is the reason the mixture is not merely untidy. .NET is written in American English:
`Color`, `Serializer`, `AuthorizationPolicy`, `IPipelineBehavior`, `Initialize`, `CancellationToken`.
A repository that writes British prose around American APIs produces comments whose subject and whose
object spell the same word differently in one line, and a reader has to decide, every time, whether
the difference is meaningful. It never is.

A count is not a convention. Nothing in this repository said which spelling to use — CLAUDE.md
required English and meant *not another language*, which is a different question — so the dominant
spelling was a fact about the past rather than an instruction about the future.

## Decision

**American English is this repository's spelling, everywhere, and a rule fails the build when it is
not.**

- **Everywhere means everywhere.** Type, method, property, variable and parameter names; comments
  and XML documentation; error messages and technical strings; the README, the strategic design and
  the records; commit messages and pull-request descriptions. Where a British and an American form
  both exist, the American one is written: *color*, *behavior*, *organization*, *authorization*,
  *center*, *catalog*, *analyze*.
- **`EveryWordThisRepositoryWrites_UsesAmericanSpelling`** reads every file this repository writes,
  splits camel-cased identifiers into their parts, and refuses any part that appears in a pinned
  British-to-American dictionary. Prose is checked as strictly as code, because the words that go
  wrong are mostly in comments.
- **The dictionary is pinned in the rule, not pulled from a package.** A rule whose word list ships
  on somebody else's release schedule is a rule whose meaning changes without a commit. What is
  pinned is what this repository has met, plus what it can expect to meet; a word nobody has written
  costs nothing to carry and catches the day somebody writes it.
- **Words that are already the same are absent from it, and `analysis` is the one to know.** Only
  the verb moves, to *analyze*, while the noun is American already. A list that folded the two
  together would have renamed `AnalysisRules` and been wrong.
- **The sweep was mechanical and total**, and reached the published surface on purpose: the route is
  now `GET /Catalog/trainings`, the proxy's anonymous segment is `Catalog`, and the two public pages
  are `/catalog` and `/catalog/{id}`. Leaving the URL British while the code around it turned
  American is the exact inconsistency this record exists to remove, and the API has no consumer
  outside this repository — the BFF and the Blazor client are both in it, and the client is
  regenerated by a script.
- **The persisted names moved too, and that was a decision rather than an oversight.** The column is
  now `PhotoSanitizedOnUtc`; the migration `20260810090000_AddTrainerPhotoSanitization` was rewritten
  in place rather than followed by a rename; and the two outbox consumers
  `HideSuspendedTrainerCatalog` and `ShowReinstatedTrainerCatalog` were renamed although ADR 0034
  makes those names the delivery ledger's idempotency key. Each of the four replaced a name that
  differed from it by one of the substitutions this record's dictionary holds. All three moves are
  safe here for one reason, stated plainly: nothing has run against a database or an outbox outside
  the test suites, which build their schema from the model and start empty. **Against a deployed
  system none of the three would be safe** — the migration would re-run, and every past event would
  be re-delivered to two consumers that had already seen it. See *Consequences*.

## Consequences

- **The sixty-three records merged before this one keep their spelling, and that is the rule rather
  than an exception to it.** A merged record is never rewritten (ADR 0039, ADR 0040): it describes
  what was decided on its date, in the words used then, and later records quote it verbatim.
  Rewriting sixty-three of them to move a vowel would edit the account of decisions nobody is
  revisiting, and would break every quotation of a title along the way. The rule therefore reaches
  the records from **0064** onwards and says so in a named constant, so the gap is declared rather
  than discovered.
- **Those records now name types that no longer carry those names.** ADR 0063 names the port that
  strips a photograph's metadata with the British agent-noun ending; the port is `IPhotoSanitizer`.
  The mapping is mechanical and in one direction — British to American — and this sentence is the
  whole of what a reader needs to follow it.
- **`docs/adr/README.md` is checked row by row rather than as a file.** Every row quotes the title of
  the record it links to, so the rows pointing at 0001–0063 are skipped and every row added after
  this one is governed. Excluding the file wholesale would have let the index drift the moment it
  gained a row.
- **A published URL changed.** The three catalog routes are now `/Catalog/...`, and the Blazor pages
  with them; the segment they replaced spelled the same noun the longer way. Any address anybody had
  bookmarked stops working. This is a
  breaking change to an API whose only consumers live in this repository, and it is the price of the
  convention being true rather than nearly true.
- **The migration history was rewritten, not appended to.** A database that had already applied the
  migration under its former name would apply `AddTrainerPhotoSanitization` on top of it and fail on
  a column that already exists. That is acceptable exactly once, on the day the migration shipped and
  before anything ran it, and the alternative — a `RenameColumn` migration — would have documented a
  spelling in the schema history forever.
- **Two outbox consumers changed identity.** A ledger holding rows written under the former consumer
  names no longer matches the consumers that wrote them, so every event those two have ever handled
  would be handed to them again. Empty ledgers make that harmless here; a future rename of a consumer
  name is not a spelling question and needs its own record.
- **The rule cannot see the file that declares its own dictionary.** `AmericanSpellingRules.cs`
  necessarily contains every British word the repository refuses, so it excludes itself. That is one
  file where a British spelling could hide, and naming it here is cheaper than pretending otherwise.
- **`.editorconfig` and `.gitignore` were reached by the rule and missed by the sweep**, because the
  script that performed the sweep read a leading dot as part of the name rather than as an
  extension. Four words survived in two files, and the rule caught all four. That is the first thing
  this rule did, and it is a fair account of why the convention is a test rather than a paragraph.
- **A word this repository has not met yet is not governed.** The dictionary is finite: the doubled
  consonant of *traveling* is in it, the doubled consonant of *wagon* is not. A rule that tried to be
  a dictionary would be wrong more often than a rule that is a list, and the list grows the day
  something slips through.

## Alternatives considered

**Write the convention in CLAUDE.md and stop there.** It is what was asked for, and it is what every
convention in this repository started as before somebody noticed that a paragraph nobody executes is
a preference. ADR 0013 makes the rule mandatory for exactly this reason: the drift that produced
`AdrCatalog` beside a controller spelling the same noun the other way happened under prose that was
not enforced because it did not exist.

**Adopt a spell-checker — `cspell`, `vale` — with a British-English dictionary inverted.** A real
dictionary, maintained by somebody else, covering words this list will never hold. It also adds a
Node toolchain to a .NET repository, needs its own ignore list for every identifier and acronym in
the codebase, and moves the definition of "correct" outside the commit that changes it. The rule
here is forty lines and reads the same tree the other 178 read.

**Rename the internal code and leave the old segment on the wire.** No URL breaks, and the argument
for it is real: a published address is a promise. It also leaves the repository holding both spellings
of its central noun, with the boundary between them being *whether a type name happens to reach a
route template* — which is not a distinction anybody can hold in their head. The convention would be
true of the code and false of the product.

**Keep British English, since the repository was already 90 % British.** Consistency is the goal,
and the incumbent spelling is the cheaper way to reach it — the sweep would have been forty words
instead of fourteen hundred. It loses to the framework: `Color`, `Serializer`, `Authorization` and
`Behavior` are not negotiable, they are what .NET is called, and a repository whose own words
disagree with its API surface has moved the inconsistency rather than removed it.

**Check identifiers only, and let prose be prose.** Half the work for most of the value, since a
misspelt type is the one that shows up in a signature. It also gives up on the larger half: 251 of
the occurrences found were in records, 598 in tests, and almost all of those were in comments. The
sentences are what a reader reads.

## Verification

- **`EveryWordThisRepositoryWrites_UsesAmericanSpelling`, watched failing with 1211 findings** before
  the sweep — every one of them a real British spelling, across 168 files — and green after it. A
  rule proven by the size of what it caught rather than by a fixture written to break it.
- **The rule caught what the sweep missed.** The sweep and the rule share one dictionary — the script
  parses it out of the rule's own source, so the two cannot disagree about a word — and they still
  disagreed about a *file*: `.editorconfig` and `.gitignore` were governed by the rule and skipped by
  the script. Four words, in two files, found by the thing that is supposed to find them.
- **Clean Release build from deleted `bin/` and `obj/`, zero warnings**, with `TreatWarningsAsErrors`
  and `EnforceCodeStyleInBuild` on, after 314 files were rewritten and 47 renamed.
- **The generated client was regenerated**, and holds no British spelling: the schema names follow
  the contracts, and the contracts moved.
- **Every suite that runs without Docker is green**, unchanged in count: the sweep renamed test
  classes and their subjects together, so no fact was lost or silently skipped.
- **`BothHosts_PublishTheSameOperations` holds** across the route rename: both hosts moved together,
  which is what that rule exists to notice.
- **The two integration suites need Docker and did not run here.** They are named rather than
  claimed green; what they exercise — the renamed route, the renamed column, the renamed consumers —
  is precisely what this record's persisted-name decision rests on.
